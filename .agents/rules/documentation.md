# Documentation Rules

Documentation is part of the architecture contract.

- Keep requirements technology-neutral unless technology is itself a constraint.
- C4 context diagrams show people/systems, not internal classes.
- Container diagrams show deployable/runnable units and data stores.
- Component diagrams show logical responsibilities.
- ADRs explain a significant choice, alternatives, consequences, and reconsideration conditions.
- Update documentation when implementation intentionally changes documented behavior.
- Do not rewrite architecture documents merely to make implementation deviations appear compliant.
- Mermaid diagrams should remain readable and should not mix unrelated abstraction levels.
